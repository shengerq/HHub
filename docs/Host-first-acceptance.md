# 主体优先实施与验收

日期：2026-11-09。状态：执行顺序与退出标准，未代表任务已经实现。依据用户最新要求，先确定体系，再修改和验收 Hhub 主体，最后按确定接口增加真实插件。

## 当前唯一主任务

把 Plugin-system-v1.md 与 Plugin-certification-and-kinds.md 的设计收敛为可执行合同：明确清单、能力与消息 schema、接口输入输出、错误码、状态、生命周期、认证负载和版本规则。此前架构草案不是已经冻结的 SDK。

通过两个不操作真实硬件的模拟夹具校对合同：设备夹具覆盖身份、DPI 复杂值、写入读回、失败和断连；功能夹具覆盖开关、预设、可选服务、后台持续任务和退出恢复。这些夹具是测试工具，不是先开发或预装两项真实功能。

合同满足两类需求后实现主体，不同时迁移全部旧插件。发现通用合同缺口先集中修正规范与测试，不在窗口代码中加入插件特例。

## 主体改造边界

主体保留窗口导航、基础设备发现、插件安装/认证/启停/通信及必要公共服务。EQ、监测、远控、Windows 设置、型号适配、开发者工具与场景自动化为按需扩展，不以默认关闭替代不安装。现有能力先保留在旧构建中作为参考，新主体验收版使用独立数据目录，不自动修改用户已有插件、配置或厂商设置。

保留现有布局和成熟交互，逐项替换主体内部公共边界，不无目标地重做全部页面。无插件时显示准确的空状态，不加载模拟设备或虚假指标。

## 主体必须通过的验收

| 项目 | 通过条件 |
| --- | --- |
| 空主体 | 无插件也能启动、导航和退出；无 EQ、监测、远控等业务后台，不产生无必要业务监听 |
| 主体安装 | 全新安装、修复、覆盖安装和失败恢复可验证；不捆绑可选插件，不擅自启用开机启动 |
| 主体更新与迁移 | 更新前检查插件与数据兼容；预设、场景和设置不丢失，失败恢复旧程序及相匹配的数据 |
| 主体完整卸载 | 停止并移除主体与受管插件、后台、缓存、更新残留、受管备份及注册的启动项/任务，不留下仍运行的受管进程 |
| 清单与认证 | 正确认证包可安装；未知签名、篡改、缺失/新增负载、已知撤销及不兼容合同被明确拒绝 |
| 包生命周期 | 安装、更新、回退和卸载完整；失败保留旧版和用户数据；安装不额外执行包代码 |
| 运行生命周期 | 按需启动、停用优先、无需求停止；持续任务有明确原因；异常不无限重启 |
| 通信 | 握手、请求配对、超时、取消、损坏消息、进程退出及重启符合合同，不误报成功 |
| 设备与状态 | 多实例、断连、重连、过期、只读和状态未知区分准确，不错用其他目标 |
| 操作协调 | 页面与公共服务共用请求路径；资源冲突和 revision 冲突有确定结果；不自动重复非幂等操作 |
| 两类模拟夹具 | 设备与功能插件均可仅通过公开接口接入，增加第三个夹具也不修改主体品牌分支 |
| 页面 | 声明式、WebUI 及选定的认证原生 UI 路线遵守合同；主题、缩放、反复进入和释放通过 |
| 后台与退出 | 关闭页面、隐藏、恢复、正常退出、后台异常均不泄漏无需求进程或订阅 |
| 轻量 | 测量冷启动、前台、后台空闲及模拟持续任务的总 CPU/内存；在固定环境确定预算并回归 |
| 开发者使用 | 依照文档从空目录构建模拟插件、校验和打包，不阅读主体源码也可完成 |

认证是来源和完整性准入，不等于病毒绝对不可存在。上述测试不以实现通用操作系统沙箱为前置条件。离线撤销信息与高权限依赖边界依照认证设计说明。

自动检查与界面实测分别记录。需点击或截图确认的项目不能由文件存在或控制台通过代替。主体验收过程中发现的现有全量测试失败也需解决；当前临时 EXE 清理失败仍是已知基线问题。

## 安装 更新与卸载的强制边界

主体自己的安装、卸载、更新和失败恢复属于首阶段能力，不留待未来插件补齐。免安装交付也须有清理受管插件和注册项的入口，不能以删除主程序文件夹代替完整卸载。

程序版本、插件接口版本、预设数据版本分别记录。预设使用稳定插件 ID、能力 ID 和格式版本，不能绑定安装路径、显示名、数组位置或 UI 布局。主体迁移自己拥有的容器与引用；插件私有格式由插件的迁移规则处理，主体不能猜测重写。

更新前预检已安装插件、场景绑定、预设和设置。无法验证兼容或缺少必需迁移器时阻止此次更新并解释原因，不静默删除配置、重置默认值或跳过插件。兼容验证包含历史插件原包和真实旧格式夹具，不能只比较版本数字。

更新采用暂存、校验、备份和提交，正确处理主体/插件运行与文件占用。中断、迁移失败或新版本启动失败时恢复旧程序及匹配的数据快照。不能把新格式交回不认识它的旧程序，不能覆盖用户更新后新产生的数据；实现时明确回退窗口与新数据保留策略并测试。

卸载停止主体、插件和受管辅助进程，恢复应恢复的临时修改，移除安装目录和用户目录中的受管程序、插件、专用 WebView 数据/缓存、下载解压暂存、更新残留、受管旧版备份、快捷方式、自启动及受管任务。不能只删除主程序而留下插件后台或维护服务。

个人预设、场景与配置提供明确的导出或保留选择；完整移除模式清理这些受管数据。保留个人数据不等于保留插件程序、运行时副本、缓存或启动项。用户自行导出的文件不属于清理范围。无交互卸载的数据策略也须明确并测试。

每个认证包申报程序、配置、缓存、日志、辅助任务和依赖的位置与所有权。清理依据经过验证的受管记录，不按插件任意提供的路径无条件删除。工作区开发源码与历史构建归档不属于软件安装的清理范围。

不误删共享系统组件、第三方应用及其他软件共用的驱动。插件独占驱动等系统依赖须在安装时记录清理方案，不能声称仅删插件文件便已移除驱动。文件清理失败、进程未退出或需重启时准确报告并提供完成路径，不能显示虚假的“已完全卸载”。

必测：携带旧插件与旧预设升级、中断、迁移失败、启动失败、回退、插件运行中卸载、保留配置后重装、完整移除后重装，以及进程/启动项/受管残留审计。主体更新不得捆绑新可选功能。

## 交付与阶段转换

主体验收交付一个独立可运行构建、同版本 SDK 合同与文档、两个模拟夹具、测试结果、已知问题和资源测量。只标记实际通过的项目，不因旧版本曾通过就自动继承结论。

主体达到上述门槛后，再按确定接口重写 VT3X Max，并随后接入通用 EQ 等功能插件。真实设备支持有自己的协议和实机门槛，不将“主体已验收”当作“设备已支持”。未来新增插件原则上只修改插件及注册数据，公共接口扩展按版本政策处理。
