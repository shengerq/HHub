# Hhub 手机远控设计 v1

手机在浏览器打开 Hhub 的远端界面。手机发送操作请求，电脑上的 Hhub 执行并回传结果。设备识别、插件后台、权限、场景和预设仍由电脑统一管理。

0.1.0 已接入局域网 HTTPS、扫码确认和撤销、系统与外设查看、场景切换、插件目录查看及手机端主题。插件市场和管理页面当前只读。应用型插件的手机控件、音量与 Windows 设置等操作属于后续扩展。

0.1.1 默认使用检测到的局域网 IPv4 和 8443 端口。首次打开远控开关时生成本地 HTTPS 证书，页面给出供手机导入的公开证书文件。签发根证书的私钥仅在生成时使用，服务端私钥由 Windows 当前用户的数据保护机制保护。手机首次连接需手动信任证书。保留个人证书指纹和自定义监听参数。

## 电脑端入口和页面

手机远控是可选插件，用户在「插件」页安装、停用或卸载。安装后由插件声明导航入口，在侧边栏「插件」下方显示手机图标和「手机远控」。卸载后移除入口。主体提供通用的导航位置和开关绑定，手机图标、页面及连接参数由插件声明。

侧栏展开时，远控开关放在「手机远控」同一行的右侧。点击图标或名称打开页面，点击开关只启停远控服务。侧栏折叠时保留对齐的手机图标，打开页面后在标题右侧提供同一个开关。两种布局绑定同一服务状态。

```text
侧边栏                  手机远控
                        ┌─────────────────┬──────────────────┐
插件                    │ 扫码配对        │ 连接参数         │
手机远控         [开关] │                 │ 连接状态         │
设置                    │    二维码       │ 访问地址         │
                        │                 │ 网络接口 · 端口   │
                        │                 │ 已配对设备       │
                        └─────────────────┴──────────────────┘
```

两列沿顶边对齐。左列二维码保持正方形，扫码后由桌面确认配对。右列每个参数一行，名称靠左、值靠右，长地址可复制。优先显示连接状态、HTTPS 地址、局域网接口、端口和已配对设备数。证书配置和设备撤销放在各自参数行的详情中。窄窗口将两列上下排列，二维码保持可扫描尺寸。

| 服务状态 | 开关 | 二维码区 |
| --- | --- | --- |
| 已关闭 | 关 | 显示「远控已关闭」 |
| 启动中 | 等待后台确认 | 显示「正在启动」 |
| 等待配对 | 开 | 显示短时一次性配对码 |
| 配对码过期 | 开 | 显示「重新生成」入口 |
| 启动失败 | 回到关 | 显示原因，右侧定位到证书、端口或接口等对应参数 |

安装后服务默认关闭。浏览设置页面时可查看和保存参数。只有开关开启且后台确认监听成功后，才生成二维码。0.1.0 支持一个有效会话，最长八小时。关闭服务会停止监听并作废二维码和会话，重新开启后需要再次配对。停用或卸载插件也会关闭服务。

桌面端验收时检查安装前后入口变化、「插件」下方的位置、折叠与展开的对齐、开关失败回退、二维码失效和两列在窄窗口下的排布。

## 手机界面

首次配对后，可从浏览器将 Hhub 网页应用添加到手机主屏幕。入口使用现有 Hhub 图标，打开后恢复已配对电脑的会话。按桌面截图沿用窄图标侧栏，依次排列主页、场景、插件和已安装且可远控的功能入口。底部保留当前场景和设置。电脑端的「手机远控」入口不出现在手机上。[iPhone 添加网页应用](https://support.apple.com/en-az/guide/iphone/iphea86e5236/ios) · [Android 安装网页应用](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid)

| 页面 | 手机排布 |
| --- | --- |
| 主页 · 系统 | 顶部保留四张监测卡。第一行 CPU、GPU，型号在各自标题下对齐。第二行内存、网络与磁盘。内存与显存显示已用和总量，GPU「温度」保留核心和显存读数。下载和上传分别标明，磁盘容量和温度按可用宽度排列。 |
| 主页 · 设备 | 在系统下方显示分组设备列表。每行显示类别图标、名称、连接方式和可用电量。外设列表来自桌面设备发现。 |
| 场景 | 顶部显示现有场景及选中态，可切换场景。下方按行显示当前场景的设备和绑定配置。 |
| 插件市场 | 「市场 / 管理」切换。市场展示主体已取得的目录。 |
| 插件管理 | 显示已安装插件、运行或停用状态。 |
| 设置 | 管理手机端的主题和断开操作。 |

页面沿用桌面内容结构，按窄屏宽度适配触屏。侧栏使用统一线条图标和简短标签，系统与设备分区纵向排列，系统四格保持两列。标题和分组列表沿同一列对齐，控件保留触屏点击范围。手机主屏幕图标使用稳定访问地址，首次配对二维码只用于授权。

首版采用适合触屏的页面映射。桌面界面和手机可使用不同布局，均从同一状态源读取，并使用相同的命令、参数和资源标识。手机修改期间显示等待状态，收到桌面回执或实际读数后更新。电脑切换场景、改动设置或断开外设时，同步刷新手机界面。

后续可由插件声明适合手机的控件和可远程调用的命令。桌面插件原有的 WinUI 或 WebUI 页面继续在 Hhub 内运行，手机使用公共声明渲染。

## 桌面执行链路

```text
手机浏览器
  ├─ HTTPS POST 发送命令
  └─ HTTPS 轮询接收状态，操作请求直接返回回执
           ↕
Hhub 手机远控插件后台
  ├─ 网页、配对、会话和授权范围
  └─ 通过受控协议请求主体执行
           ↕
Hhub 主体命令入口
  └─ 公开状态与场景切换
```

远控插件复用主体的场景切换、插件启动、资源冲突处理和命令回执。主体逐项校验会话授权、插件启用状态、目标设备实例和参数。插件控制仍由对应的电脑后台执行，主窗口在托盘时也可接收允许的命令。手机只看经授权的状态字段。安装、卸载、驱动授权和涉及提权的操作继续在桌面确认。

第一版协议提案为 `remote.controls.v1`。插件公开控件标识、关联命令、数据类型、允许值、状态字段和作用资源。每次请求携带请求 ID 与设备实例，重复提交同一请求返回已有结果。涉及同一资源的请求由主体排序执行。预设和场景引用稳定 ID，并继续接受已兼容的旧参数。对于没有读回能力的操作，回执标明「已发送」或「未确认」。

## 连接和配对

默认在同一局域网内使用，电脑主动开启远控后才监听指定的私有 IPv4。首次由桌面生成两分钟有效的一次性二维码，手机扫码后在桌面确认。批准后换成可查看状态和切换场景的会话。电脑可以撤销当前会话。

手机浏览器需信任当前 HTTPS 证书。使用自动生成证书时，手机先导入页面给出的公开证书文件。访问地址改变或证书到期更新后需要重新导入。用自有域名时，可通过 DNS-01 取得证书，并让局域网 DNS 把域名指向电脑。这样电脑无需对公网开放端口。扫码配对负责授权，TLS 负责验证手机连到的是哪台电脑。[DNS-01 说明](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge) · [Kestrel HTTPS 配置](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/kestrel/endpoints?view=aspnetcore-10.0)

会话 Cookie 采用 `Secure`、`HttpOnly`、`SameSite=Strict`。所有写操作检查站点来源和防跨站请求令牌。配对限制有效期、尝试次数和并发，二维码原始令牌及会话密钥不进入日志。首版只发布明确允许的动作，手机没有任意命令、文件访问或桌面输入的通用入口。[浏览器会话管理](https://developer.mozilla.org/en-US/docs/Web/Security/Authentication/Session_management)

## 内存与生命周期

远控后台默认关闭。用户启用后在托盘继续等待连接，并声明保活原因。手机页面可见时每两秒读取状态，只有主页维持系统监测需求。手机离开主页或断开连接后，该需求在最后一次续期的六秒后到期。手机远控本身不需要加载 Windows 端的 WebView。

远控后台复用 Hhub 提供的 .NET 运行环境。ASP.NET Core HTTPS 组件随可选插件交付，空闲及连接后的内存占用需在实机验收时测量。

## 实现与验收顺序

1. 先做受信 HTTPS、扫码确认、会话撤销和只读主页。在 Android Chrome 与 iPhone Safari 上验证添加主屏幕、从 Hhub 图标启动、配对、断网、重连和撤销。
2. 接通音量、静音、媒体和场景，让桌面操作与手机操作互相可见。测试同一设置在两端连续操作及失败回执。
3. 接入 Windows 设置与通用插件控件，选一个现有插件验证按需启动、实例匹配、预设选择和回读。其余插件沿用同一契约接入。
4. 验证托盘运行、退出和安装更新时的连接行为。比较远控关闭、无人连接和一个手机订阅时主体与后台的专用内存，检查撤销后停止推送。
