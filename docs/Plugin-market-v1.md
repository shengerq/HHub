# 插件市场与持续任务

设置 → 插件分为“管理”和“市场”：管理区先显示插件目录，再列出全部已安装插件；市场区可添加、编辑和删除多个 JSON 索引地址，支持 HTTPS，本机测试允许 HTTP。原有单网址配置自动兼容，修改后保存为多网址列表，删除最后一个市场不会恢复旧地址。未配置地址时仍可使用随附插件包和本地安装。检查更新只检查，找到新版后再次点击更新才下载安装。

最多配置 32 个市场，网址规范化后去重。刷新与更新检查读取所有配置的市场，按插件 ID 合并并选择最高版本；同一版本按配置顺序选择第一个来源。插件列表显示被选中市场的主机名，提示可查看完整来源地址。各市场独立读取，一个市场失败仍展示其他市场结果，并显示失败原因；部分市场不可用时不报告“没有更新”。

索引结构：

```json
{
  "schemaVersion": 1,
  "plugins": [
    {
      "id": "example.plugin",
      "name": "示例插件",
      "version": "1.0.0",
      "description": "功能说明",
      "packageUrl": "packages/example.plugin-1.0.0.hhub",
      "sha256": "填写插件包实际 SHA-256 的 64 位十六进制值"
    }
  ]
}
```

下载地址可相对索引定位。索引限制 2 MiB、单包限制 256 MiB；不自动跟随重定向。包必须通过 SHA-256、插件 ID 和版本一致性检查，再交由现有安装流程执行兼容性校验、停止旧后台、备份与替换。旧插件的启用、停用选择保留；历史“保持运行”偏好统一解释为按需启动。

插件默认按需启动。已有 `supportsBackgroundActivity` 和实时 `backgroundActivity: true` 仍可维持正在执行的持续任务。确实需要从主程序启动时就持续运行的集成插件可声明：

```json
{
  "supportsBackgroundActivity": true,
  "persistentTaskReason": "持续采集用户开启的设备状态",
  "requiredCapabilities": ["background-persistent.v1"]
}
```

必须提供真实、简短的原因，且使用 `stdio-v1`。持续任务形成运行需求，不覆盖用户停用和主程序完整退出。旧主体不支持该能力时应在安装阶段拒绝。具体资源释放与恢复仍遵循插件开发准则。

赞助页使用 `Assets/Sponsor-design-v1.png` 作为可替换的设计预览。实际赞助按钮链接到用户提供的爱发电页面；设计图中的生成二维码未验证，不作为支付入口。
