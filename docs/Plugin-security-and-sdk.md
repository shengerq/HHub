# 插件技术选型 安全边界与开发者交付

日期：2026-11-09。状态：历史安全方案参考。用户考虑个人维护成本后已选择收敛为 [认证准入与统一插件分类](Plugin-certification-and-kinds.md)。下文强制沙箱、通用硬件代理及隔离原型的顺序不再是首版交付要求；开发文档与协议语义要求可作为参考。现有 Hhub 没有因此获得沙箱或稳定 SDK。

## 1 技术选型建议

| 部分 | 官方首选 | 边界 |
| --- | --- | --- |
| 清单、能力和设备支持描述 | JSON 与 JSON Schema | 只含数据，不执行安装脚本；约束字段、长度、深度、取值和版本 |
| 插件业务与协议解析 | C#，首个实现环境为 .NET 10 | 独立受限进程，使用版本化 SDK；语言本身不是安全保障 |
| 高性能算法或现有原生库 | C/C++ 等原生代码 | 走相同公共合同，原生依赖和额外权限单独审核，不因签名而豁免隔离 |
| 简单页面 | 主体渲染的能力描述 | 不要求额外浏览器或原生 UI DLL |
| 复杂第三方页面 | HTML/CSS/TypeScript，构建后交付本地静态资源 | WebView2 承载；普通用户不用安装 Node.js；仅通过受限桥接访问主体 |
| 原生 WinUI 页面 | 官方或单独审核的可信组件 | 普通第三方包不向主体进程加载任意 UI DLL |
| 控制通信 | 版本化 UTF-8 JSON Lines | 仅为控制面；跨语言 SDK 不暴露主体内部 ABI |

设备没有“必须使用某种编程语言”这一要求，它接收 HID 报告等协议数据。C# 可以实现协议解析，C++ 也可以；真正决定适配的是正确的设备识别、报文和状态语义。

面向第三方的目标结构为：界面 → 主体控制服务 → 插件协议逻辑 → 受控硬件访问组件 → Windows HID/其他已支持传输 → 设备。Windows HID 支持用户态读取与发送报告，不要求为每个型号开发内核驱动。非标准设备是否需要厂商服务、签名驱动或其他传输须单独验证，不承诺所有设备都能直接用通用 HID 控制。

硬件访问组件负责校验调用插件、实际设备实例、报告类型/长度、协议允许范围及频率；不向普通插件暴露任意系统路径、任意设备句柄或无限制系统调用。原始 HID 代理若只是无条件转发字节，并不能阻止破坏设备。型号协议范围必须经过核对和审核，不能由恶意插件自行声明后立即获准。

音频 PCM 等高吞吐数据不编码成 JSON Lines。第一版优先在音频插件进程内完成采集、DSP 和播放；确需跨进程传递时另外定义有界、可审计的数据通道，不改变控制协议的既有语义。

## 2 主体通信必须固定的语义

SDK 封装握手、发现、状态、事务、事件、取消和退出。开发者实现设备逻辑，无需重写管道读写、请求配对和超时处理。

主体发出能力调用，插件执行设备协议并独立读回后报告结果。消息发送、Windows API 返回成功和硬件设置已确认是不同阶段。界面展示能力 ID、值和状态，不从日志文字猜测结果。

请求关联、事务幂等、revision 冲突、超时后查询、取消后的状态和重启恢复必须进入协议 schema 与测试。退出前必须明确释放句柄、保存持久配置和恢复临时系统修改的语义。

## 3 漏检恶意代码时的防护

杀毒软件不扫描压缩包并非普遍事实。Microsoft Defender 文档说明默认允许归档扫描，但排除策略、引擎状态、文件格式与限制可能影响结果。无论扫描包还是解压后的文件，都不能把无告警视为代码安全证明。

以下是待实现的分层目标，不是现有 Hhub 的安全能力清单：

1. **不执行的安装检查：** 校验路径、大小、文件数和嵌套限制；拒绝加密或无法检查的包；不执行安装脚本、不加载 DLL 获取元数据、不自动运行依赖安装器。
2. **暂存并扫描：** 先在受限暂存区解压，扫描全部有效负载和依赖，再校验固定文件集合与摘要。记录所用引擎、时间、结果和不可扫描状态；引擎不可用或扫描失败不得显示“安全”。不擅自更改杀毒排除项、关闭防护或上传作者源码。
3. **来源与审核：** 发布者身份、源码和依赖审查、可追溯构建、对最终包签名及版本撤销共同作用。签名证明来源和字节完整性，不能证明代码没有恶意行为；更新也必须重新检查。
4. **运行限制：** 第三方代码默认不拥有主体权限。验证 AppContainer 等操作系统隔离方案，限制访问用户文件、网络、其他进程和自身数据之外的位置；设备和系统设置访问走受控组件。文件句柄、IPC ACL、动态依赖和子进程同样审计，不能只在 C# 层封禁 API 名称。
5. **页面隔离：** 普通第三方只提供声明式页面或受限本地 WebUI。不在主体中加载其原生 UI DLL；验证消息来源、参数、目标与权限；限制外部导航、网络请求、下载、弹窗和原生对象暴露。需要 CSP 与资源请求策略，不是仅阻止页面跳转。
6. **损害控制：** 设置超时、请求速率、内存/CPU 预算和异常终止；提供停用、撤销、回退及日志。异常监管不能可靠识别全部恶意行为，不能宣传自动发现所有病毒。

AppContainer 的实际 .NET/原生库运行、设备代理、音频实时性及进程资源限制需要原型验证。普通权限进程、低优先级、AssemblyLoadContext 和 manifest 权限字符串不能替代这些验证。隔离不成立时不静默退回无限制执行，也不向普通用户开放任意未知代码并标记为安全。

暂时无法受限运行的原生 DSP、系统组件或驱动集成作为扩展信任范围单独审核，明确其额外权限和剩余风险。它们遵守同一插件协议，不另建一套不兼容插件体系。开发模式不能借此进入普通分发或绕过固件操作范围。

沙箱也不能保证绝对安全，尤其无法单独证明厂商协议不会损害设备。权限边界、受控接口、代码审查与实际硬件验证共同降低风险。

## 4 面向开发者与 AI 的文档包

开发者交付是一个版本化、可离线使用的 SDK 包，不能只有架构介绍，也不能要求阅读 Hhub 源码。文档和机器合同共同构成公开接口的权威来源。

| 文件或目录 | 必须内容 |
| --- | --- |
| README / 快速开始 | 平台要求、安装 SDK、创建、构建、校验、调试、打包的真实可执行命令 |
| SPEC | 主体与插件职责、生命周期、身份、能力、事务和完整消息流程 |
| schemas | 清单、协议、能力、错误与服务合同的 JSON Schema，以及有效/无效示例 |
| API 与错误码 | 每个操作的输入、输出、前置条件、结果、超时、取消及恢复语义 |
| SDK 库 | 版本化 C# 合同与运行辅助；原生最小示例；不引用 Hhub 内部类 |
| examples | 最小只读插件、可写模拟设备、结构化能力、WebUI、公共服务消费 |
| security | 允许的设备和系统访问方式、文件/网络权限、依赖及签名要求 |
| conformance | 离线校验器、测试宿主、故障注入、参考轨迹和明确通过/失败结果 |
| compatibility / changelog | 支持矩阵、弃用周期、数据迁移和各版本变化 |
| AI 开发入口 | 固定 SDK 版本、最小必读集合、真实命令、示例位置和验收条件 |

AI 开发入口必须明确：不能编造 API、设备报文、型号身份、默认值或硬件通过证据；未知协议返回未实现。模拟器必须显式标记，不伪装真实硬件。生成器默认不发送硬件写入，开发者补齐协议实现并完成验证后才声明可写。

机器 schema 不能覆盖所有运行时语义，文档也不能代替校验器。SDK 发布要求文档示例在 CI 从空目录完成构建、虚拟调试和打包。新增版本用历史已发布插件原包回归，不重新编译来掩盖接口变化。

## 5 下一阶段的可验收产物

先固定威胁模型与权限清单，验证一个没有文件/网络权限、只能读取模拟设备的受限 C# 插件和本地页面；再验证一个受限原生示例。证明越权被拒绝、进程失败不影响主体、退出释放资源之后，再冻结进程与硬件访问合同。

同时完成最小可执行 SDK、schema、示例与文档，使第三方在不看主体源码的情况下通过一致性测试。随后把 VT3X Max 的真实协议移入统一硬件边界，并验证跨类型 EQ/键盘需求。

当前尚无这些新 SDK、schema 或隔离原型。本文不能单独让第三方生成可加载的新体系插件；它定义下一阶段需要真正交付并测试的内容。
