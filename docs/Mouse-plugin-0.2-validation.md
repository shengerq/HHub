# 鼠标插件 0.2.0 验证记录

2026-11-03。用户反馈：VT3S MAX 可以被找到，但 Feature 查询失败；设备名称、图片没有映射；不接受独立设置窗口。

根因之一是 0.1.0 强制要求 Feature 头回显地址、bank 和长度。本地 ClickSync 协议注释明确记录 `01 00 00 00 [payload]`，FerrisPulse 的读路径也是在头后取值，未要求这些保留字段回显。0.2.0 接受保留头及带回显变体；无回显时二次串行查询比较，保留 Busy/错误/截断和写后回读检查。用户目前提供的是错误截图，尚未提供本版实际 TX/RX，因此不将此修正等同于真机已验证成功。

设备识别改为两层：清单声明静态产品名称/图片，快照通过物理设备或成员实例补充自定义名称和实时状态。即使控制读取失败，识别信息仍保留；电量仍受数据时效限制。图片来自插件包本地 JPEG，来源见插件第三方声明。

主体新增通用 WebUI 容器与全内容区声明；插件自带 HTML/CSS/JS，独立 WinForms 面板及 openPanel 命令已移除。WebUI 命令经主体清单校验后派发 stdio 后端。

已通过：鼠标协议/控制/元数据/包安装 71 项检查、真实前端 JS 的 8 项离线交互检查、主体核心 138 项检查；主体和鼠标界面模块编译 0 警告 / 0 错误。发布后端的描述符枚举、stdio 错误回执及退出检查通过。没有在本机启动 Hhub 桌面界面或执行鼠标设置写入。

已核对发布包包含界面模块、HTML/CSS/JS 和两处图片资源；对应源码 ZIP 解压后的精简解决方案（后端、界面模块、共享 UI 与核心、测试）复建成功，0 警告 / 0 错误。

完整解决方案检查曾被本轮未修改的 `plugins/Hhub.SystemMonitor/HardwareSampler.cs:21` 中 `PawnIo.IsLoaded` 静态调用编译错误阻止。本轮交付主体项目与鼠标插件独立编译发布，不重新编译监测插件，监测随附包沿用已存在的 0.4.3。

交付：`artifacts/Hhub-0.5-MouseWeb.zip` 为新版主体和鼠标插件一体包；`artifacts/hhub.mouse-0.2.0.hhub` 为单独插件；对应源码与 SHA-256 同目录。用户先退出托盘旧版，运行新版主体，再拖入插件更新。WebView2 运行时由目标 Windows 系统提供。

尚待目标设备复测：Feature 实际布局、型号与端点、DPI/回报率写入及恢复、充电/电量、有线与 2.4G、原生 WebView2 宿主页面交互和设备图片加载。异常可在当前鼠标页导出 JSON 诊断，无需打开独立配置窗口。
