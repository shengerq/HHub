# Hhub 插件预设兼容改造

同一个插件包在受支持的新旧 Hhub 主体中，应能列出、选择和应用同一份用户预设。覆盖安装主体、切换免安装版或升级插件后，场景绑定仍应指向原来的预设。

给各插件开发对话的任务文案：

> 请按统一的预设兼容规则修改本插件，并用同一个插件包在新旧主体上验证。先比较实际加载的插件版本、用户数据路径、预设列表快照和选择命令参数，查明数据在哪里丢失。保留用户预设、场景绑定和旧数据备份。提交时附上版本对照及验证结果。

1. **固定数据位置。** 预设由插件保存到当前用户的持久数据目录，按插件 ID 区分。切换主体目录、重装主体或升级插件不改变读取位置。已有插件沿用原目录。确需迁移时先备份，兼容读取旧目录，成功读回后才记录迁移完成。
2. **固定预设身份。** 新预设使用稳定 ID，显示名可以更改。配置选项公开 `label` 和稳定 `value`。对历史上以名称保存的预设，保留名称到 ID 的映射，已有场景中的旧值仍能解析。内置预设与用户预设同名时要能区分，禁止覆盖用户内容。
3. **保持协议兼容。** 同一能力版本内保留预设列表、当前选择和应用命令的字段名、参数类型与含义。先继续接受现有参数，再增加新字段或别名。旧主体无法承载新增界面能力时，按清单声明能力并明确报告；可以继续读取旧预设时应保留入口。
4. **保留原始数据。** 新旧格式通过 `schemaVersion` 识别。新版本可读旧格式，旧版本读到不支持的数据应保留原文件并提示。迁移和保存写入临时文件，校验成功后再替换；失败时保留上一次可用数据。查不到绑定的预设时显示缺失并允许重新选择。
5. **验证实际应用。** 选择预设或场景触发后检查设备回读或插件确认结果。需要保存到设备时，同时校验真实设备实例。打开界面、读到文件或显示预设名都不能代替应用确认。

验收时分别用新旧主体加载同一个插件包。用旧版新建并绑定一份用户预设，覆盖安装主体后验证列表、选择、实际应用和场景触发。再测试预设改名、两款同名预设、缺失文件和降回旧主体的行为。发布记录写明最低支持的主体构建、插件版本及数据格式版本；仅写「Hhub 0.5」不足以区分同版本号下的能力差异。

优先核对 FXsound 的 `audio.presetOptions`、`audio.preset`、`applyPreset` 与 `savePreset`。当前接口以 `name` 作为应用参数，耳机集成和场景绑定也会传入旧名称。若插件增加稳定 ID，旧 `name` 参数和历史保存文件须一并兼容。这份文案定义后续整改要求，具体故障需用用户遇到的主体、插件包和预设文件复现。
